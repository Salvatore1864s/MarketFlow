
# Architecture Decision Records

## ADR-001: Использование микросервисной архитектуры

Статус: Принято

Контекст:
Практика требует разработки системы из нескольких взаимодействующих сервисов с отдельными базами данных.

Решение:
Использовать четыре микросервиса: Identity, Catalog, Order, Inventory.

Причина:
Разделение ответственности и независимость данных.

## ADR-002: PostgreSQL для хранения данных

Статус: Принято

Решение:
Использовать PostgreSQL для всех микросервисов, при этом каждый сервис получает собственную базу данных.

Причина:
Поддержка транзакций, надёжность и совместимость с Entity Framework Core.

## ADR-003: RabbitMQ для событий

Статус: Принято

Решение:
Использовать RabbitMQ для асинхронного взаимодействия сервисов.

Причина:
Слабая связанность и возможность обработки событий независимо от отправителя.

## ADR-004: Saga и Outbox

Статус: Принято

Решение:
Использовать Saga для управления распределённым процессом заказа и Outbox для надёжной публикации событий.

Причина:
Необходимость компенсации операций при сбоях и предотвращения потери событий.
