
# Архитектура MarketFlow

## 1. Цель и контекст

MarketFlow — маркетплейс для покупателей и продавцов.

Основные сценарии:
- Регистрация и авторизация.
- Просмотр и поиск товаров.
- Управление товарами продавцом.
- Добавление товаров в корзину.
- Создание и обработка заказов.
- Резервирование товаров на складе.
- Эмуляция оплаты.
- Отслеживание состояния заказа.

## 2. Общая архитектура

Система состоит из React-клиента, API Gateway и четырёх микросервисов.

## 3. Микросервисы

### Identity Service
Ответственность:
- Регистрация пользователей.
- Авторизация через JWT.
- Роли User, Seller, Admin.
- Профили пользователей и продавцов.

База данных: PostgreSQL.

### Catalog Service
Ответственность:
- Товары.
- Категории.
- Поиск и фильтрация.
- Управление товарами продавца.

База данных: PostgreSQL.

### Order Service
Ответственность:
- Корзина.
- Создание заказов.
- История заказов.
- Управление статусами.
- Оркестрация Saga.
- Outbox Pattern.

База данных: PostgreSQL.

### Inventory Service
Ответственность:
- Учёт остатков.
- Резервирование товаров.
- Освобождение резервов.
- Подтверждение списания товара.

База данных: PostgreSQL.

## 4. Инфраструктура

- YARP — API Gateway.
- RabbitMQ — обмен событиями.
- Redis — кэширование.
- SignalR — уведомления в реальном времени.
- Docker Compose — запуск системы.
- GitHub Actions — автоматическая сборка и тестирование.

## 5. Взаимодействие сервисов

React отправляет запросы через API Gateway.

Сервисы взаимодействуют синхронно через HTTP и асинхронно через RabbitMQ.

Каждый микросервис владеет собственной базой данных. Прямой доступ к базе другого сервиса запрещён.

## 6. Процесс заказа

1. Покупатель создаёт заказ.
2. Order Service сохраняет заказ.
3. Outbox сохраняет событие для публикации.
4. RabbitMQ доставляет событие Inventory Service.
5. Inventory Service резервирует товар.
6. Payment (эмуляция) выполняет оплату.
7. При успехе заказ подтверждается.
8. При ошибке выполняется компенсация Saga.
9. Пользователь получает уведомление через SignalR.

## 7. Безопасность

- JWT-аутентификация.
- Ролевая авторизация.
- Проверка прав на стороне сервера.
- Хранение паролей в виде хэшей.
- Секреты через переменные окружения.

## 8. Тестирование

Используется xUnit.

Планируются:
- Unit-тесты бизнес-логики.
- Интеграционные тесты API.
- Тесты Saga и компенсаций.
- Нагрузочный тест.

## 9. Статус

Документ описывает целевую архитектуру. По мере реализации он будет обновляться в соответствии с фактическим состоянием проекта.
